# Kiro 内工具链路自检提示词

来源：Cursor 会话 `38dfd587` 2026-09-03，用户要求「生成一段提示词，让我能检查通过 api4kiro 的模型在工作区和 Kiro IDE 能调用所有工具，同时能派发子代理，子代理同样能够调用所有工具」。这是本产品在真实 Kiro 内唯一的端到端手工验收流程；`scripts/check-*.js` 只覆盖几何与语法。会话导出中未见执行记录。

用法：把下面代码块整段粘进 Kiro 聊天框。跑两遍：一遍普通模型，一遍开思考 / 高 effort 档位（工具循环里的 `reasoningContent` 签名延续只有开思考才会被测到）。先开 `api2kiroDual.debug`。用 Autopilot 或在自定义 agent 里设 `tools: ["*"]` 并把子代理加入 `toolsSettings.subagent.trustedAgents`，否则几十次工具调用会被审批弹窗卡住。

判读：`NOT_EXPOSED` = Kiro 没把该工具下发给模型（Kiro 配置问题，与代理无关）；`FAIL` 且错误来自上游 / 解析 = api2kiro 或中转站问题；子代理清单与主代理不一致 = 子代理 agent 配置的 `tools` 收窄了。

````text
你现在是「工具链路自检代理」。目标：在当前工作区里，逐个真实调用你能拿到的每一个工具，并派发子代理做同样的事，最后输出一份可核对的报告。本次只关心"工具能否被正确调用、结果能否正确返回"，不关心业务逻辑。

## 0. 规则（必须遵守）
1. 所有写操作只能发生在沙盒目录 `.toolcheck/`（相对工作区根目录）内，任务结束前把它整个删掉。不要改动、删除沙盒之外的任何文件。
2. 不要执行任何破坏性命令（删除非沙盒路径、git reset/checkout/push、安装/卸载全局软件等）。
3. 严禁编造结果。只有当工具真正返回了输出、且你把关键返回内容原样贴进报告，才算 PASS。任何"我认为应该可以"一律算 FAIL。
4. 某个工具调用失败先原样重试 1 次；仍失败则把完整错误信息逐字记录，不要概括。
5. 需要我授权的工具就正常发起并等待，不要跳过。
6. 整个流程在本会话内一次性跑完，不要中途停下来问我是否继续（第 4 节第 3 步除外）。
7. 每个阶段结束先输出该阶段的小结表，再进入下一阶段。

## 1. 工具清单盘点
动手前，先列出你当前上下文中全部可用工具的准确名称（以工具定义里的 name 为准，不要凭记忆写），按以下分类，每个工具写一句用途：
读取类 / 写入类 / Shell 与进程类 / 诊断类 / Web 类 / 上下文与会话类（如 disclose_context、introspect、todo_list、user_input 等）/ 子代理类 / MCP 工具（按 server 分组）/ 其它未归类。
同时回答：你当前使用的模型标识是什么（能拿到就如实写，拿不到就写"未知"）。

## 2. 主代理逐个实调（每个工具至少真实调用一次）
先创建 `.toolcheck/main/`，然后按顺序执行，每步写明"用了哪个工具 → 返回了什么"：
a. 写入：创建 `.toolcheck/main/a.txt`，内容 3 行，必须同时包含中文、emoji、双引号、反斜杠、制表符和一段 JSON 字符串（检验参数转义链路）。
b. 追加：在 a.txt 末尾追加一行 `appended-line`。
c. 精确替换：把 a.txt 中的 `appended-line` 改成 `replaced-line`。
d. 读取：读回 a.txt 并原文贴出，确认 a/b/c 三步内容全部正确。
e. 读图：用 glob 在工作区找一个 png/jpg，用读取工具读它并用一句话描述图中内容（检验图片类工具结果链路）；找不到图片就 SKIP。
f. 大参数：写一个 `.toolcheck/main/big.md`，不少于 300 行、每行带行号（检验工具参数流式传输是否完整），写完读回并核对首行、第 150 行、末行和总行数。
g. 多文件读取：如有多文件读取工具，一次读 a.txt 和 big.md（可带行号范围）。
h. 目录列表：列出 `.toolcheck/` 和工作区根目录。
i. 文件搜索（glob）：搜 `**/*.md` 和 `.toolcheck/**/*.txt`。
j. 内容搜索（grep）：在工作区搜正则 `replaced-line|appended-line`，应只命中 a.txt。
k. 代码智能：如有 code/符号搜索类工具，对工作区任意源码文件查一次符号或大纲。
l. Shell：执行一条前台命令，输出当前目录、当前时间以及 `echo "中文 ✅ \"quoted\""`；再执行一条必然失败的命令（如访问不存在的路径），确认非零退出码和 stderr 能正确回传。
m. 后台进程：如有后台进程类工具，启动一个持续输出的进程（每秒打印一次、共 5 次），用读取进程输出工具取一次输出，用列进程工具列出，然后停止它。
n. 诊断：如有 diagnostics 工具，对工作区任意源码文件取一次诊断（无诊断也算 PASS，只要工具正常返回）。
o. Web：用 web_search 搜 `Kiro IDE built-in tools`；用 web_fetch 抓 `https://kiro.dev/docs/tools/`；各贴出返回的前 200 字符。
p. 上下文/会话类：todo_list 建 3 个待办并把 1 个标记完成；introspect 问一个关于 Kiro 自身的问题；disclose_context 如存在则调用一次；每个都贴返回。
q. MCP：对第 1 节列出的每一个 MCP server，至少调用 1 个只读类工具（list/get/search 一类），贴返回；某 server 没有只读工具则说明原因并标 SKIP。
r. 并行调用：在同一轮回复里同时发起至少 3 个互不依赖的工具调用（如同时读 3 个文件，或同时 glob + grep + 列目录），确认 3 个结果都正常返回（专门检验一轮多 tool_use 的链路）。
s. 删除：删除 `.toolcheck/main/big.md`，再列目录确认它消失。

## 3. 子代理派发（核心）
使用子代理工具（invoke_subagent / subagent 一类）同时并行派发 2 个子代理 A 和 B，不要串行。给每个子代理的任务说明必须原样包含以下内容：

> 你是子代理 {A|B}。只允许在 `.toolcheck/sub-{A|B}/` 内写文件。请先列出你自己上下文中全部可用工具的准确名称（按读取/写入/Shell/诊断/Web/上下文/子代理/MCP 分类），然后对每个工具至少真实调用一次：写文件（含中文和特殊字符）、追加、替换、读回、列目录、glob、grep、执行一条 shell 命令、web_fetch 抓 https://example.com 、todo_list、每个 MCP server 至少一个只读工具。接着尝试用子代理工具再派发一个"孙代理"，让它只做一件事：写并读回 `.toolcheck/sub-{A|B}/grandchild.txt`（如果你没有子代理工具或被拒绝，请原样记录）。禁止编造；任何工具调用失败先重试 1 次，再逐字记录错误。最后返回一份 Markdown 表格：工具名 | 结果(PASS/FAIL/SKIP/NOT_EXPOSED) | 关键返回摘要或逐字错误。另外单独回答：你能看到的工具总数、你使用的模型标识、是否成功派发孙代理。

子代理返回后，你必须：
- 原样贴出 A 和 B 的完整报告，不删减。
- 对比主代理与 A、B 的工具清单是否一致，列出差集（子代理缺哪些、多哪些）。
- 用列目录 + 读文件验证 A、B（以及孙代理）声称写过的文件真实存在、内容一致。不能只信子代理的话。

## 4. 清理与收尾
1. 删除整个 `.toolcheck/` 目录，列目录确认已不存在。
2. 如果工作区是 git 仓库，执行 `git status --porcelain` 并贴出结果，确认除本任务外无任何改动。
3. 最后用 user_input（如存在）向我提一个确认问题："自检完成，是否需要我把报告写入文件？"——这是为了检验交互式提问工具；无论我如何回答，都不再改动任何文件。

## 5. 最终报告（Markdown，放在最后）
### 5.1 总览
- 主代理：可见工具数 / 实调成功数 / 失败数 / 未暴露数
- 子代理 A、B：各自的上述四个数字
- 孙代理派发：A 成功/失败，B 成功/失败
- 一轮并行多工具调用：PASS/FAIL
- 大参数（300 行写入）流式传输：PASS/FAIL
- 特殊字符转义（中文/emoji/引号/反斜杠/制表符）：PASS/FAIL
- 图片工具结果：PASS/FAIL/SKIP
### 5.2 明细表
| 工具名 | 分类 | 主代理 | 子代理 A | 子代理 B | 备注（逐字错误 / SKIP 原因） |
状态只能取四个值：PASS（真实返回并核对）、FAIL（调用了但报错或返回不符）、SKIP（存在但因安全/无只读操作未调）、NOT_EXPOSED（不在本次工具列表中）。
### 5.3 结论
一句话回答：通过当前代理链路的这个模型，能否在 Kiro IDE 中完整调用所有工具、并派发出同样能调用所有工具的子代理？如果不能，逐条指出哪个环节出问题、原始错误是什么。
````
